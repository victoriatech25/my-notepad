# ADR 0002 — Markdown 미리보기 렌더러

- 상태: **결정됨** (P0-08 사용자 승인, 2026-10-20) — P0-10에서 문서화
- 관련: PLAN.md §2.5, §3.8 · 측정: [docs/measurements/phase0.md](../measurements/phase0.md) P0-08, P0-09 · UX 백로그 UX-004

## 배경
PLAN.md §3.8의 핵심 요구는 소스·미리보기·분할 모드를 자연스럽게 오가는 것이다. 특히 분할 모드의 **양방향 스크롤 동기화**와 **미리보기 더블클릭 → 소스 줄 이동**을 위해서는 "블록별 소스 줄 범위 ↔ 화면 y좌표" 대응이 필요하다.

| 방식 | 내용 |
| :--- | :--- |
| A | `egui_commonmark` 0.26 (egui 0.37 대응) |
| B | `pulldown-cmark` 0.13으로 파싱 + 자체 블록 모델·렌더러 |

## Phase 0에서 확인한 사실
| 항목 | A | B |
| :--- | :--- | :--- |
| 블록 위치 대응 | **얻을 수 없음** (`show()`가 위치를 돌려주지 않음, 내부에서만 사용) | PLAN.md 98블록, 1MB 1,980블록 전부 대응, 줄·y 모두 단조 증가 (자동 점검) |
| 화면 모양 (사용자 비교) | 1차 비교에서 "전반적으로 나음" (UX-004) | A 규칙(제목 단계 크기·진한 색 강조·여백·글머리·인용선·표 틀)으로 다듬은 뒤 사용자 승인 |
| 스크롤 성능 (1MB) | — | 전체 그리기 26ms → 보이는 블록만 1.4ms (P0-09) |
| 스크롤 동기화 | 비율 근사만 가능 | 양방향 동기화·되먹임 없음 사용자 확인 (P0-09) |
| egui 업그레이드 | 크레이트의 대응판을 기다려야 함 | 파서는 egui와 무관, 렌더러는 직접 수정 |

## 결정
**B 채택.** 블록 모델은 UI와 분리된 `core::markdown`(PLAN.md §4.3)으로 옮기고, 렌더러는 A의 화면 규칙을 따른다. 굵게·제목은 기본적으로 진한 색으로만 강조하고, 실제 굵은 글꼴 사용은 옵션으로 남긴다.

## 기각한 대안
| 대안 | 기각 이유 |
| :--- | :--- |
| A 그대로 사용 | 블록 위치가 없어 §3.8 동기화 품질 기준(같은 제목이 양쪽 화면 높이 10% 이내)을 맞출 수 없음 |
| A 포크 후 위치 공개 | 원본 업데이트·egui 업그레이드를 계속 직접 따라가야 함. 모양은 B에서 이미 맞춤 |

## 결과
- 이미지, 각주, Front Matter, 링크 동작, 원시 HTML 표시 등은 직접 구현해야 한다 (Phase 3 범위, PLAN.md §3.8-4).
- 화면 모양을 A 규칙에 맞춘 것은 `docs/ux/ui-spec.md`에 Markdown 미리보기 명세로 옮긴다 (P3-UX).

## 재검토 조건
- `egui_commonmark`가 블록 위치(소스 범위 ↔ 화면 좌표)를 공개 API로 제공하게 되면, 유지보수 비용을 다시 비교한다.
