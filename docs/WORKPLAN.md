## 0. 진행 규칙

### 0.1 진행 방식
1. 작업은 **WU 단위**로 진행한다. 개발자가 직접 `진행 중`으로 두는 WU는 한 번에 하나다.
2. WU는 아래 **완료 조건을 모두 충족**해야 `완료`로 표시한다. 각 Phase의 WU는 번호순이 아니라 **Phase별 "수행 순서"**를 따른다.
3. Phase의 모든 WU가 완료되면 **Phase 게이트 검증**을 수행하고, 통과해야 다음 Phase를 시작한다.
4. 검증에 실패하면 해당 WU를 `재작업`으로 되돌리고, 실패 내용을 §9 검증 기록에 남긴 뒤 수정한다. **실패한 WU에 의존하는 WU는 시작하지 않는다.**
5. **검증 대기 중 병행**: WU가 `검증 대기(👤/🎨)` 상태인 동안, 그 WU에 의존하지 않는 다음 WU(주로 🤖만 있는 `core` 로직)를 진행할 수 있다. 사용자의 회신이 오면 회신 처리(재작업 포함)를 최우선으로 한다.
6. 진행 중 PLAN.md의 결정이 바뀌면 PLAN.md를 먼저 고치고 이 문서의 관련 WU를 갱신한다.

### 0.2 검증 구분 표기

| 표기 | 의미 | 수행 주체 | 판정 |
| :--- | :--- | :--- | :--- |
| 🤖 **자동 검증** | 빌드, 단위/통합 테스트, 정적 검사, 측정 스크립트 | 개발자(Claude) | 명령 결과로 판정 (출력 결과를 검증 기록에 첨부) |
| 👤 **사용자 화면 검증** | 앱을 직접 실행해 기능이 **정확히 동작하는지** 확인 | **사용자** | 체크리스트 항목별 ✅/❌ 회신으로 판정 |
| 🎨 **UX 검증** | 화면 배치·흐름·문구·시각 피드백이 **쓰기 편한지** 평가 | **사용자** | 항목별 `좋음` / `개선 필요` / `다시 설계` + 의견 회신 (§0.7) |
| 🍎 **macOS 검증** | macOS에서만 확인 가능한 항목 | 사용자 (MacBook Pro, §0.8) | 위와 동일 |

- 👤 / 🎨 표시가 있는 WU는 **사용자의 회신 없이 완료 처리하지 않는다.** 개발자는 WU 구현 후 검증 요청(§9.1 양식)으로 실행 방법과 체크리스트를 전달하고 회신을 기다린다.
- macOS 장비(MacBook Pro)를 확보했으므로 🍎 항목은 **같은 WU 안에서 Windows 항목과 함께 수행**한다. `보류(🍎)`는 장비를 일시적으로 쓸 수 없을 때만 허용하며, **Phase 0 게이트(IME Go/No-Go) 전에는 macOS IME 검증을 반드시 완료**하고 **Phase 5 게이트 전까지 모든 🍎 보류를 해소**한다.
- 👤 체크리스트는 Phase 5의 릴리스 회귀 테스트용 `docs/manual-test.md`로 누적한다.

### 0.3 WU 공통 완료 조건 (Definition of Done)
모든 WU는 개별 검증 항목에 더해 아래를 만족해야 한다 (Phase 0 스파이크는 1·2만 적용).

1. 🤖 `cargo build` 성공 (경고 0)
2. 🤖 `cargo clippy --all-targets -- -D warnings` 통과
3. 🤖 `cargo fmt --check` 통과
4. 🤖 `cargo test` 전체 통과 (기존 테스트 포함 — 회귀 없음)
5. WU에 명시된 🤖 / 👤 / 🍎 검증 항목 전부 통과, 🎨 항목은 회신을 받고 `개선 필요` 의견을 §9.4 UX 백로그에 등록
6. 변경된 동작이 PLAN.md와 다르면 PLAN.md 갱신

### 0.4 WU 상태 값
`대기` → `진행 중` → `검증 대기(👤/🎨)` → `완료` / `재작업` / `보류(🍎)`

### 0.5 규모 표기
**S**: 반나절 이하 · **M**: 1~2일 · **L**: 3일 이상 (참고용 추정치)

### 0.6 UI/UX 조기 검증 원칙
UI와 사용성은 **구현이 끝난 뒤가 아니라 가능한 한 빨리** 사용자 확인을 받는다. 늦게 발견된 UX 문제는 구조 변경으로 번지기 때문이다.

1. **화면 우선(Outside-in)**: 사용자에게 보이는 기능은 내부 로직보다 **화면을 먼저** 만든다. 내부가 준비되지 않았으면 가짜 데이터나 단순 구현(예: UTF-8 전용 열기/저장, 동기 검색)으로 화면을 먼저 연결해 🎨 검증을 받고, 이후 내부를 교체한다.
2. **전체 화면 프로토타입을 맨 처음에**: Phase 0에서 앱의 모든 주요 화면(메뉴, 탭, 사이드바, 에디터, 상태 표시줄, 찾기 바, Markdown 3모드, 대화상자)을 가짜 데이터로 클릭해 볼 수 있는 프로토타입(P0-UX1)을 만들고, 확정된 배치를 `docs/ux/ui-spec.md`로 고정한다. 이후 모든 UI WU는 이 명세를 따른다.
3. **짧은 검증 주기**: 개발 기준 **2~3일(또는 WU 2~3개)마다 사용자가 직접 써 볼 수 있는 빌드**를 낸다. 검증 요청은 가능하면 묶어서 보내 사용자의 확인 횟수를 줄인다.
4. **검증 마찰 최소화**: `cargo xtask try <시나리오>` 한 줄로 빌드·실행·샘플 파일 열기까지 되게 한다 — Windows·macOS 공통 명령 (예: `cargo xtask try encoding`은 인코딩 픽스처 4개를 탭으로 연 상태로 실행). 앱에는 개발용 `--demo <시나리오>` 인자를 둔다. Windows에서 에이전트가 직접 창을 띄울 때는 격리 데스크톱(`WinSta0\exebox-...`)이나 셸 종료로 창이 닫히지 않도록 `xtask`가 `WinSta0\Default` 데스크톱을 명시하며, 에이전트는 `cargo xtask try <시나리오> --wait`(`IsDaemon: true`)로 실행한다 ([AGENTS.md](../AGENTS.md)).
5. **UX 반영 WU**: Phase마다 마지막에 `Px-UX` WU를 두어 그 Phase에서 모인 UX 피드백을 반영하고 재확인을 받는다. 게이트는 **UX 백로그 `필수` 0건**이어야 통과한다.

### 0.7 🎨 UX 검증 회신과 백로그 처리
- 회신 형식: 항목마다 `좋음` / `개선 필요` / `다시 설계` 중 하나 + 자유 의견 (스크린샷에 표시해 주면 가장 좋다)
- `개선 필요`, `다시 설계`는 §9.4 **UX 백로그**에 등록하고 사용자와 우선순위를 정한다
  - `필수`: 다음 게이트 전까지 반드시 반영 (`다시 설계`는 기본 `필수`)
  - `권장`: 해당 Phase의 `Px-UX` WU에서 반영
  - `보류`: Phase 6 백로그로 이관
- 반영한 항목은 다음 검증 빌드에서 사용자가 재확인한 뒤 닫는다
- 확정된 UX 결정(배치, 문구, 색, 단축키)은 `docs/ux/ui-spec.md`에 기록한다
- 🎨 UX 검증은 Windows와 macOS 양쪽에서 받는다. 두 OS에서 의견이 다르면(예: 단축키 습관, 메뉴 위치) OS별로 다르게 할지 `ui-spec.md`에 결정을 남긴다

**장비 전환 규칙**
1. **작업 시작 시**: `git pull --rebase` 로 최신 상태를 받는다.
2. **장비를 떠나기 전**: 작업 중이던 내용을 커밋하고 `git push` 한다. 미완성이면 WU 브랜치에 `wip:` 커밋으로 올린다. **한 장비에 커밋하지 않은 변경을 남겨 두고 다른 장비에서 같은 파일을 고치지 않는다.**
3. **브랜치**: WU마다 `wu/<WU-ID>-<짧은-설명>` 브랜치(예: `wu/P0-01-spike-skeleton`)를 만들고, WU 완료(검증 통과) 시 `main`에 병합한다. `main`은 항상 두 OS에서 빌드되는 상태를 유지한다.
4. **검증 커밋 고정**: 사용자 검증 요청에는 커밋 해시를 적고, Windows와 macOS에서 **같은 커밋**으로 검증한다.
5. **같은 WU를 두 장비에서 동시에 진행하지 않는다.** 동시에 진행해야 하면 서로 다른 WU 브랜치에서 한다.

**두 OS 공존을 위한 저장소 설정 (P0-00에서 구성)**
- **줄바꿈**: `.gitattributes`에 `* text=auto eol=lf`(소스는 LF)를 두고, **`tests/fixtures/**`와 `spikes/samples/**`는 `-text`(바이너리 취급)** 로 지정한다. 이 프로젝트는 CRLF/LF·인코딩 픽스처를 바이트 그대로 검사하므로, Git이 줄바꿈을 바꾸면 테스트가 장비마다 다르게 나온다. Windows에서는 `git config core.autocrlf false`.
- **Rust 버전 고정**: `rust-toolchain.toml`로 두 장비의 Rust 버전·구성요소(rustfmt, clippy)를 일치시킨다. `Cargo.lock`은 커밋한다.
- **개발 보조 명령은 `cargo xtask`로 통일**: PowerShell(`.ps1`)·셸(`.sh`) 스크립트를 따로 두지 않고 Rust로 작성해 두 OS에서 같은 명령(`cargo xtask try <시나리오>`, `cargo xtask measure`)을 쓴다.
- **경로**: 코드·설정에 장비별 절대 경로를 넣지 않는다. OS별 경로(폰트, 설정, 로그 위치)는 `cfg(target_os)` 분기로만 처리한다.
- **파일 이름**: 대소문자만 다른 파일 이름을 만들지 않는다(두 OS 모두 기본적으로 대소문자를 구분하지 않는 파일 시스템).
- **무시 목록**: `.gitignore`에 `target/`, `.DS_Store`, `Thumbs.db`, IDE 폴더 등을 둔다.
- **편집기 설정**: `.editorconfig`로 들여쓰기·끝 개행·문자 인코딩(UTF-8)을 맞춘다.
